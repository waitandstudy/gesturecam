# GestureCam 手势文法（规格）

> **状态：已实现**（2026-09-25）。实现落在 `src/core/gesture/handShape.ts`（手型判定）
> + `GestureManager`（每只手一个手型状态机）+ `InteractionManager`（急停与重新武装）。
> 实现过程中发现的三处需要修正的地方见文末 §7，验收见 §8。
>
> 这份文档**先于实现存在**：它规定手势的含义，代码按它实现，验收按它检查。
> 目的很直接 —— 手势必须有明确的文法，否则"识别到的手势"和"用户想做的事"
> 之间会长期对不上，表现为"很容易识别错误"。
>
> 核心约定（用户提出，鼠标类比）：**拇指与食指捏合 = 鼠标左键**。
> 它既是唯一的选择入口，也是这套文法的锚点。

---

## 0. 一句话总览

| 手势 | 鼠标类比 | 作用 |
| --- | --- | --- |
| 拇指 + 食指捏合 | **左键按下** | 唯一的选择入口：抓住光标下的素材 |
| 捏着移动 | 按住拖动 | **只改位置，绝不改大小** |
| 另一只手也捏合 | **按住 Shift** | 进入缩放修饰态：两手**分开 = 放大**，**靠近 = 缩小** |
| 握拳 | **Esc** | 取消**这只手**的操作（另一只手不受影响） |
| **拇指扣住食指尖再甩开（指弹）** | **拖进废纸篓** | **删掉手里抓着的那张图**（没抓着才删指尖下最上层；2 秒淡出期，期间捏住即可撤销） |
| 松开捏合 / 用抓着素材的那只手张开手掌 | 左键抬起 | 释放 |

## 1. 手型（离散状态，带迟滞）

手型是**静态判定**（看某一帧的手长什么样），动作是手型的**组合与变化**。
所有量都做成**尺度无关**的比例，手离摄像头远近不影响判定。

| 手型 | 判据 | 含义 |
| --- | --- | --- |
| `FIST` 握拳 | **食指 + 中指**深蜷（平面与深度两把尺子都成立） | 取消这只手的操作（**优先级最高**） |
| `PINCH` 捏合 | ① 拇指尖-食指尖距离 / 掌心长度 < `0.50`；② **且**（食指伸展 **或** 食→中夹角 θ > `25°`） | 选中 |
| `OPEN` 张开手掌 | 至少 3 指伸展，且拇食指距离比例 > `0.60` | 释放 |
| `OTHER` | 以上都不是 | 什么都不做 |

判定**按上表顺序**，先命中先算（握拳优先，见 §1.2）。

### 1.1 为什么捏合要靠"食→中夹角"（第二个维度）

**只靠"拇食指距离"这**一个**维度，握拳和捏合是重叠的** —— 握拳时拇指常常压在
食指上，两指尖距离同样很小。这会直接违反文法：用户想急停，系统却以为他要抓。

第二个维度用**食指相对中指的夹角 θ**：

```
θ = angle( 食指MCP → 食指TIP ,  中指MCP → 中指TIP )
```

**关键点：θ 是"食指相对中指"的差值，两根手指共同的部分被抵消了。**

| 姿势 | 食指向量 | 中指向量 | θ |
| --- | --- | --- | --- |
| 张开手掌 | 朝上前方 | 朝上前方 | 小（≈5–15°） |
| **握拳** | 卷向掌心 | 卷向掌心 | **小**（≈0–20°） |
| **捏合** | 屈向拇指（侧向） | 保持朝前 | **大**（≈30–60°） |

**⚠️ 参考系绝对不能用"手掌轴线"。** 如果用 `手腕→中指MCP` 当"伸直方向"，
握拳时食指卷向掌心，相对手掌轴线会变成一个**大**角度 —— 就和捏合混在一起了。
必须用**中指自己的朝向**当参考：握拳时食、中两指同步蜷曲，
所以**相对**角度反而保持很小。这是这个方案能成立的原因。

**θ 是强信号，但不是唯一门槛。** 残留情况：有人捏合时是"食指伸直、拇指去碰食指侧面"，
此时食指没有屈向拇指，θ 很小。这一格由"**食指伸展**"兜住（见下表第 2 行），
所以仍然认作 `PINCH`。若把 θ 做成硬条件，这类用户会被判丢掉。

| 拇食指 gap | 食→中夹角 θ | 食指状态 | 判定 |
| --- | --- | --- | --- |
| 小 | 大 | — | `PINCH` 常规捏合（食指屈向拇指） |
| 小 | **小** | **伸展** | `PINCH` "直捏"（拇指去碰伸直的食指） |
| 小 | 小 | 蜷曲 | `FIST` 握拳（拇指压在蜷曲的食指上） |
| 大 | 小 | — | `OPEN` 张开手掌 |
| 大 | 大 | — | `OTHER`（例如比"耶"、指指点点） |

**由此带来的一处简化（重要）**：捏合**不再要求**"中指/无名指/小指伸展"。
那条硬条件原本的风险是"真人捏合时无名指小指常常自然半蜷，会被拒判" ——
现在食指的蜷曲度**只**用于握拳检测，这个风险就消失了。

### 1.1.1 握拳为什么只认食指+中指（真机反馈后改的）

第一版要求**四指全部蜷曲**，真机上出了两个问题：

1. **"深层捏合"被读成握拳。** 捏得紧的时候，无名指与小指会自然蜷进掌心 ——
   那不是握拳，是捏。而握拳的优先级高于捏合，于是用户"选中之后再也选不中"。
2. **"松开拳头但手还半握着"的放松手被读成握拳。** 旧的蜷曲阈值（平面 1.15）
   太松，把放松手（≈1.2）也算了进去。

现在的判据只认**食指 + 中指**：**中指才是诚实的信号** —— 捏合根本不用中指，
所以"中指深蜷"就等于"这只手没有在做捏合"。无名指与小指太容易跟着姿势漂，
不参与握拳判定。阈值也收紧到平面 `1.10` / 深度 `1.20`
（真拳头 ≈0.95–1.05，放松手 ≥1.2）。

### 1.1.2 两个尺子：平面距离 + 含深度的三维距离

```
reach     = |指尖 - 手腕| / 掌心长度                （平面投影）
reachDepth = |指尖 - 手腕|₃ / 掌心长度（含 MediaPipe 的 z）
```

- **"伸展"取"或"**：平面**或**深度任一成立就算伸展 —— 透视缩短时平面读数会塌缩，
  不能因此判成蜷曲（那会拒判正常捏合）。
- **"蜷曲"取"与"**：两把尺子同时说蜷曲才算 —— 握拳会锁住操作，是最不该误判的状态。

> **一处诚实的更正**：我原本以为"手指朝向镜头"的透视缩短是握拳误判的成因，
> 但写测试时发现**比值本身对透视缩短不敏感**（指尖与掌根一起塌缩）。
> 真凶是上面 §1.1.1 的两条。三维距离保留下来当第二道门：
> 手掌长度估计一旦异常，比值会整体漂移，两把尺子同时成立才更稳。

### 1.1.3 手型必须是"这一帧看到了什么"

**看不到手时，`shape` 必须是 `other`。** 这句看起来像废话，但它是真机
"张开手了还是抓不住"的根因：第一版在"这一帧没看到手"时对非捏合手型直接返回，
槽位里**留着上一次的 `fist`**，而交互层拿 `controls.pinches[].shape`
判断"能不能重新武装"—— 那份陈旧手型让门槛永远解不开。

所以现在把两件事**分开**：

| 字段 | 含义 | 手离开画面时 |
| --- | --- | --- |
| `shape` | 这一帧看到的手型 | 立刻变 `other` |
| `active`（会话标志） | 捏合会话是否还按着（宽限期内为真） | 宽限期内仍 `true`，`center` 为 `null` |

### 1.1.4 两个量的度量

```
gap  = |拇指尖 - 食指尖| / |手腕 - 中指MCP|      （掌心长度归一化，天然尺度无关）
θ    = 两个指向量之间的夹角（2D 投影）
reach(指) = |指尖 - 手腕| / |手腕 - 中指MCP|
         伸展 ≈ 1.35 以上     蜷曲 ≈ 1.10 以下（真拳头 ≈0.95–1.05，放松手 ≥1.2）
```

- θ 用 **MCP→TIP 整根手指**的方向，不要用 `PIP→TIP` 末节：
  末节太短，2D 投影的噪声会把它淹没。
- θ 天然与手离摄像头的远近无关（夹角不随尺度变化），所以不需要再除以掌心长度。
- 对称性检查：正反手（手背/手心朝向镜头）时两个指向量会一起翻转，**θ 不变** ——
  所以前后摄像头、左右手都不需要额外处理。

### 1.2 优先级：`FIST` > `PINCH` > `OPEN`

**任何情况下，只要一只手判为握拳，就当作急停。**
即使另一只手正捏着、即使某只手的拇食指恰好也靠得很近，都按取消处理。
急停优先于一切，这是它存在的意义。

### 1.3 迟滞与最短保持

- 每个手型各有**进入/退出两个阈值**
  （捏合 gap：ENTER `0.50` / EXIT `0.60`；夹角：ENTER `25°` / EXIT `18°`）
- **`PINCH` 进入走单帧判定**（保延迟，捏下去就抓）；**`FIST` / `OPEN` 需要连续保持 2 帧（约 60ms）**
  - 为什么捏合可以放宽：有了"第二只手不参与抓取"（§2.2 第 3 条），
    误判一次 pinch 的代价从"抓错一张图"降成"多进一次缩放态"，风险已经很低；
    而取消类动作误判的代价是"正在拖的图突然掉"，更疼，所以给它 2 帧确认。
- 手型切换不是"每帧重新投票"，而是**带状态的迟滞**（和现在的 pinch 判定同一套机制）
- 手型变化时允许直接跳转（`PINCH` → `FIST` 不需要先经过 `OPEN`），但**必须满足目标手型的进入条件**

## 2. 动作文法（状态机）

```
                  ┌──────────────── 取消条件 ────────────────┐
                  ↓                                          │
   IDLE ──PINCH──────────────────→ GRABBING ──另一只手 PINCH──→ SCALING
     ↑                                 │                        │
     └────────────── 取消 ─────────────┴────────────────────────┘
```

### 2.1 状态定义

| 状态 | 含义 | 位置 | 大小 |
| --- | --- | --- | --- |
| `IDLE` | 没有任何会话 | 不动 | 不动 |
| `GRABBING` | 一只手抓着**一个**素材 | 跟那只手（保持抓取偏移） | **不动** |
| `SCALING` | 一只手抓着素材，另一只手也捏合 | 跟**两手捏合中点** | 跟**两手间距** |

### 2.2 迁移规则

1. **`IDLE` + `PINCH`（某只手）** → 命中该手准星下**最上层**的可抓素材 → `GRABBING`。
   会话归属**先抓住的那只手**（`grabbedBy`）。
2. **`GRABBING` + 移动** → 拖动。**单手绝不改尺寸。**
3. **`GRABBING` + 另一只手 `PINCH`** → `SCALING`。
   - 基准 = **第二只手捏上那一刻**的两手间距
   - 素材相对两手中点的偏移被记下（避免加入瞬间跳一下）
   - **第二只手不参与命中测试，不会抓走别的素材**（它只是修饰键）
4. **`SCALING` + 第二只手离开 `PINCH`** → 回到 `GRABBING`。
   大小**停在原处**（不回弹），并以当前位置重锚（避免跳一下）。
5. 任何状态 + **取消条件** → `IDLE`，素材停在原地，**不带投掷速度**。

### 2.3 缩放方向（务必自检）

| 两手动作 | 结果 |
| --- | --- |
| 分开（间距变大） | **放大** |
| 靠近（间距变小） | **缩小** |

### 2.4 取消条件（任一满足）

- **抓着素材的那只手 `FIST`**（急停；**只停这只手自己**，见下）
- 抓着素材的那只手离开 `PINCH`（松开左键）
- 手整只丢失超过 **0.25s** 宽限期

> **握拳的作用域是"这只手"，不是"一切"**（真机反馈后定的，见 §7.1）。
> 一只手握拳只取消**它自己**的抓取会话；什么都没抓着的手握拳**什么都不做**。
> 这样屏幕里另一只手（常常只是放松搭着、还容易被判成握拳）就不会干扰它。
> 想停两只手就两只手都握拳。

> **关于"张开手掌"的语义修正（实现时定的，见 §7.1）**：
> 只有**抓着素材的那只手**张开才算放手（它的捏合随之结束 → 释放）。
> **不是**任意一只手张开就全局取消 —— 因为第二只手在两手操作时通常就是张开的，
> "任意一只手 open → 全局取消"会让双手缩放根本没法进行。

### 2.5 取消之后必须"重新武装"

取消的瞬间，用户的手指往往还在捏合的位置附近；如果立刻允许新的捏合，
**取消动作本身就会马上抓回一张图**，急停等于没用。

所以取消后置 `rearmRequired = true`，并要求：

> 直到**当初挡住的那只手**不再处于 `PINCH` 或 `FIST` 时，才清除这个标志。

**注意是"当初挡住的那只手"，不是"所有手"。** 记下取消那一刻真正处在
`PINCH`/`FIST` 的手，只有它们离开才解除 —— 否则用户另一只随手搭在画面里的手
（万一被判成握拳）会让程序**永远无法重新武装**，那比没有急停更糟。

在此之前，即使某只手的拇食指距离落在阈值内，也**不允许**建立新的抓取会话
（包括"先捏上、再移到素材上"那条宽限通道）。界面上要明说当前处于
"已取消、请先张开手"的状态，否则用户会以为程序卡住了。

**但门槛必须有安全阀。** 万一（手型判定卡住、或手的姿态古怪）一直判成握拳，
用户就再也抓不住任何东西了 —— 这比"多等一会儿"严重得多。所以：

> `rearmTimeoutSeconds`（默认 **1.5s**）：到点无条件放行。
> 急停的意图（"别让取消动作本身立刻抓回一张图"）只需要一小段时间就够。

## 3. 阈值表（初值，**全部需要真机标定**）

| 项 | 初值 | 与现状的关系 |
| --- | --- | --- |
| 捏合 gap ENTER | `0.50` | 保持不变（掌心长度归一化） |
| 捏合 gap EXIT | `0.60` | **从 1.00 收紧** |
| 食→中夹角 θ ENTER | `25°` | 新增 |
| 食→中夹角 θ EXIT | `18°` | 新增（迟滞带 7°） |
| 手指"伸展"判据 | 平面或深度 `> 1.35` | 新增 |
| 手指"蜷曲"判据 | 平面 `≤ 1.10` **且** 深度 `≤ 1.20` | 新增（真拳头 ≈0.95–1.05） |
| 握拳判据 | **食指 + 中指**蜷曲，持续 2 帧 | 新增（真机后从"四指"收窄） |
| 张开手掌判据 | ≥3 指伸展 且 gap > `0.60`，持续 2 帧 | 新增 |
| 手型最短保持 | 仅 `FIST` / `OPEN`：2 帧 / 60ms | 新增 |
| 取消后重新武装 | 需"当初挡住的那只手"离开 pinch/fist | 新增 |
| 重新武装安全阀 | `1.5s` 后无条件放行 | 新增（防锁死） |
| 指弹装填 | **拇指扣住食指尖**（`gap ≤ 0.50`）且其余三指蜷着（`middleReach ≤ 1.10`），连续 2 帧 | **第五轮真机重写**（原为"食指 ≤1.35 + gap ≥0.60 + 中指 ≥1.10"，方向是反的）；`gap` 又从 0.65 收到 **0.50**（真机"没贴住也能触发"） |
| 指弹释放 | ≤3 帧内 `gap` 比装填时张开 ≥0.25，且指尖速度 ≥0.8 | **真机重写**（原 `indexReach ≥1.60` + 速度 ≥1.5） |
| 指弹冷却 | `0.35s`（一次动作只算一次） | 新增 |
| 松手去抖 | 连续 3 帧判成 `other` 才发 `gesture-end`（`fist`/`open` 不受影响） | 新增（真机"拖动时突然松掉"） |
| 打响指（翻页） | 拇指↔中指贴住（`middleGap ≤0.50`，**且比拇指↔食指更近**）连续 2 帧 → 弹开增量 **≥0.45**、中指尖速度 **≥1.2** | 新增（§28）。两个门槛按真机**两点法**定：误触发 0.3/0.6、真响指 0.6/3.0，门槛卡中间 |
| 删除淡出期 | `2s`（期间捏住 = 撤销） | 新增 |
| 录制上限 | 时长 `5 分钟` / 体积 `400MB`，80% 起预警 | 新增 |
| 手丢失宽限 | `0.25s` | 保持不变 |
| 抓取准入窗口 | 起手后 `0.7s` 内移到素材上也算抓住 | 保持不变 |
| 抓取宽容边距 | 输出画幅短边的 `8%` | 保持不变 |

**阈值在代码里只有一个出处：`DEFAULT_HAND_SHAPE_THRESHOLDS`（`handShape.ts`）。**
改标定只改那一处，单测与验收都按它断言。

**关于 EXIT 从 1.00 收到 0.60**：当初放到 1.00 的**唯一**原因是"单手张开手指来放大"
需要余量。缩放已经交给双手之后，这个余量就不需要了 —— 收紧会显著减少误判的 pinch，
而且它让"捏合"这个手型更接近用户心里的"捏紧"。

**所有阈值都是初值，必须真机标定**（尤其 θ 的 25°/18°，个体差异可能是最大的一项）。

## 5. 需要真机确认的四个手感风险（诚实记录）

1. **θ 的阈值个体差异可能很大。**
   25°/18° 是按"常规捏合时食指会明显偏向拇指"估的，但有人捏合时食指几乎不屈
   （拇指主动去碰食指），θ 会落在 10° 左右 —— 这类人靠"食指伸展"这一格兜住，
   所以**功能上不会丢**，但那一格的判定余量更小。
   真机标定时优先看调试面板里的 θ 分布，必要时把 ENTER 降到 18°。
2. **θ 的噪声比距离比大。** 它来自两个短线段的方向，抖动比"掌心长度归一化距离"明显。
   缓解手段：迟滞带给到 7°；不把它当唯一门槛；实测下来大多数用户在
   `reach ≈ 1.5–1.8`（远超 1.35），所以**实际起决定作用的是"食指伸展"这一格**，
   θ 主要在"握拳 vs 捏合"的区分上起作用 —— 而那一格的余量很大（5° vs 40°）。
3. **握拳检测要看四指蜷曲** —— 如果真机上发现"手侧对着镜头时四指 reach 读数不可靠"，
   退路是：握拳只要求"食指 + 中指蜷曲"（两指比四指在侧视下更稳）。
4. **从"捏着"到"握拳"的过渡。** 中间必经"半握"状态，`FIST` 的迟滞 + 2 帧最短保持
   是为了让这个过渡**不产生任何中间误动作**。如果真机觉得"急停慢半拍"，
   优先缩短最短保持帧数，而不是砍掉迟滞 —— 迟滞是抗抖动的地基。

## 9. 第二批：动态手势与"不变量"

### 9.1 指弹（index flick）—— 文法里的第一个**动态**手势

需求是"删掉一张图"。候选方案筛过一轮（拖出画幅、双手握拳、三指捏合、垃圾桶区），
最后选了**"弹脑瓜"（拇指扣住食指尖蓄力 → 急速甩开）**，因为：

1. **它是过程，不是姿势** —— 静态手型只有那么几个（捏合/握拳/张开），再塞一个进去就会互相打架；
   而"从勾到弹"不占用任何静态手型。
2. **它天生带方向与速度** —— 这正是删除（选目标）和物理（冲量）都需要的信息。
   同一次检测在编辑态里是"把这张图弹掉"，在 `Phase 10` 里就是"给这个物体一个冲量"。
3. **不用新增任何 UI 区域**（垃圾桶方案需要在屏幕上常驻一块区域）。

判定规格（`flick.ts`）：

```
装填态（连续 ≥2 帧）：gap ≤ 0.65（**拇指扣住食指尖**）
                      且 其余三指蜷着（middleReach ≤ 1.10）
                      注意**不看食指**：弹脑瓜蓄力时食指本来就是伸着的（真机实测 1.52）
释放：≤3 帧内 gap 相对装填时张开 ≥ 0.25，且其余三指仍蜷着，指尖速度 ≥ 0.8（各向同性场景单位/秒）
目标：**这只手抓着的那张**素材；没抓着才回落到"食指指尖下最上层"
```

**⚠️ 第五轮真机标定把整个模型换掉了（旧版是错的，不是调参能救的）。**
用户反馈"弹脑瓜（拇指扣住食指尖蓄力、其余三指不动、食指弹出）试很多次都装填不上"，
真机调试叠层的读数：

```
flick      right pinch · 食 1.52- · gap 0.45- · 中 0.91- · 装填 0/2
           弹速 0.55-需≥1.50 · 食指需≤1.35
```

三条旧门槛**一条都不成立**，而且方向是反的：

| 旧门槛 | 要求 | 真机读数 | 问题在哪 |
| --- | --- | --- | --- |
| `loadedIndexReach` | 食指 ≤1.35 | **1.52** | 弹脑瓜的食指是**伸着蓄力**的，不弯向掌心 |
| `minGap` | gap ≥0.60（拇指躲开） | **0.45** | **方向反了**：真姿势拇指就扣在食指尖上 |
| `minMiddleReach` | 中指 ≥1.10（别蜷） | **0.91** | 其余三指本来就是蜷着不动的 |

那三条描述的是一个**不存在的姿势**（"食指弯向掌心 + 拇指躲开"）。旧版还额外有两条死路：

- 释放判定要往回找"最近一帧 `indexReach ≤ 1.35`"当起跳帧 —— 而食指全程 ≥1.45，**永远找不到**；
- 面板判出 `pinch 0.449 ACTIVE`：装填姿势**就是捏合**。于是"对着目标图蓄力"必然先把图抓起来，
  而交互层那句"正抓着东西的那只手弹一下没有意义"会直接跳过指弹 —— **永远删不掉**。

**现在的模型：靠动态区分，不再找静态姿势。**

> 静：**拇指扣住食指尖**（gap 小）+ 其余三指蜷着
> 动：**拇食指急速分离**（gap 变大）+ 食指指尖高速位移

三个量的分工：

- `loadedMaxGap`（≤0.65）—— 装填的**正面**条件（原来要求"躲开"，反了）。
  它和捏合的进入阈值 `0.50` 同一个量级，这是**刻意的**：蓄力姿势和捏合本来就是同形。
- `maxMiddleReach`（≤1.10）—— 其余三指蜷着。它挡的是**张开手掌**（那是"释放"手势），
  而不是原以为的"握拳"：握拳要求食指也深蜷，而指弹时食指是伸的，两者天然不撞（真机 `fist —`）。
- `minGapGain`（≥0.25）+ `minTipSpeed`（≥0.8）—— 弹出。
  **防误触的主力是 `minGapGain`**：抓着素材快速拖动时指尖速度同样很高，
  但那只手还在捏合、gap 不会变大。

**速度门槛为什么从 1.5 降到 0.8**：原来的 1.5 是按"一次指弹指尖移动画幅宽度的 10–20%"
估的，但那个估计**偏大** —— 弹脑瓜里食指只是从扣住的 1.52 伸到约 1.85，位移 ≈0.33 个**掌长**；
而掌长大约只占画幅宽的 0.1–0.2 ⇒ 指尖实际只走画幅宽的 **3–7%**，
真机 20fps（一帧 50ms）下算出来约 **0.6–1.4 /秒**。1.5 会把真实指弹全挡在门外。
敢调低还因为**速度已经不负责防误触了**（见上一条），而且误删有 2 秒后悔期、
弹不出来却是不可恢复的。**这个数是整条链路里最没把握的一个，需要下一轮真机读数来定。**

**删除是破坏性操作，所以给了 2 秒后悔期**：弹中之后素材半透明淡出、留在原地，
**期间再捏住它就等于撤销**，时间到才真正移除。不做"弹中即消失"——
录到一半误弹一次就只能重新加图。也正是有后悔期兜着，门槛才敢往**灵敏**那一侧偏。

**删除目标为什么优先"手里那张"**：装填姿势既然就是捏合，真机上蓄力时图**已经在手里**了。
用"手里那张"比"指尖下最上层"更贴合意图，连瞄准都省了 ——
反过来，原来那句 `if (grabbing) continue` 会让真机上永远删不掉。没抓着任何东西时
才回落到"指尖下最上层"，保证"弹空白处没有副作用"这条老行为不变。

风险与标定（诚实记录）：

- **真机只有约 20fps**（tracker 46.5ms），一次指弹只跨 **1–2 帧**，所以速度估得很粗。
  这是目前所有手势里**最依赖真机标定**的一个。
- **`minTipSpeed` 是最没把握的数**（见上）。面板会把真实读数报出来，下一轮按它定。
- 装填姿势与捏合同形，所以蓄力时素材会被抓起来高亮 —— 这**顺带解决**了
  "指弹是唯一一个做对了也没有任何反馈的手势"这个问题：抓起来的那张就是反馈。
- **真机标定的入口是调试叠层里的 `flick` 两行**（见 §9.1.1）。

#### 9.1.1 指弹的调试读数（真机排查的唯一入口）

"姿势做了却没反应"在真机上是完全不透明的：可能是拇指没扣住、可能是其余三指张开了、
也可能是甩得不够快/不够开。所以调试叠层直接把**每条门槛的读数与判定**
并排写出来（达标 `+`、没达标 `-`）：

```
flick      right pinch · 扣 0.45+ · 中 0.91+ · 装填 2/2 · 已扣住
           甩开 增0.45+ 速1.02+ · 食 1.52 · 需增≥0.25 速≥0.80
```

第一行是**扣住**（装填）：`扣` = 拇食指距离，要求**小**；`中` = 其余三指蜷着；
`食` 挪到第二行且**没有达标标记** —— 它现在纯粹是观测，不参与门槛。
末尾那条短提示只报**当前挡路的那一条**（`拇指扣住(≤0.65)` / `三指别张开(≤1.10)` / `已扣住`）。

第二行是**甩开**（弹出）：`增` = gap 相对扣住时张开多少，`速` = 指尖速度。
这两个数在甩开之后**保持不动**，供人抬眼读数 —— 标定就靠它们。
（`速` 报的就是判定真正用的那个跨帧平均速度：人抬眼看到的必须与判定一致，
否则会出现"面板说够快、程序说不够快"这种最伤信任的错位。）

两张标定截图（人工过目用）：`tools/flick-arm-hook.png`（扣住，应装填）、
`tools/flick-arm-open-fingers.png`（拇指照旧扣着但其余三指张开，不应装填 —— 面板会指出"三指别张开"）。

### 9.2 边界约束：把 `boundaryMode` 从"只存不执行"变成真的

`state.boundaryMode` 从 Phase 1 就存在，但**没有任何行为读它** —— 手一滑把素材拖出成片画幅，
它就飘在 letterbox 暗区里：命中测试算得到、用户却很难瞄准，实际体验就是"素材丢了，只能清空重来"。

现在由 `BoundaryBehavior` 在 **`constrain` 阶段**统一收口（这个阶段从 Phase 1 就预留、一直是空的）：

| 模式 | 约束 |
| --- | --- |
| `CENTER_CLAMP`（默认）/ `CLAMP` | **锚点**留在画幅内 → 中心永远可见、永远抓得回来 |
| `FULL_VISIBLE` | 整个素材（含缩放与旋转后的外框）留在画幅内 |
| `ALLOW_OVERFLOW` | 允许越界，但至少露出 15% 自身尺寸 |
| `NO_BOUNDARY` | 不约束（预留给"扔出画面"这类玩法） |

为什么放在 `constrain`：跟手、双手缩放、将来的物理都跑在它**前面**，
所以只有最后一步统一约束，才不会有哪条路径把素材漏出去。

外加一条**兜底**：任何模式下只要发现素材外框与画幅**完全没有交集**，就拉回画幅中心。
理论上前面的钳制已经保证了这一点，但这条兜底把"素材彻底丢失"从"不可能"变成
"结构上不可能"—— 它也是我自己写错钳制数学时的安全网。

## 7. 实现时对规格的修正（都写下了理由）

### 7.1 `OPEN` 的取消是**按手**的，不是全局的

规格原文（我自己起草的）写的是"任一只手 `OPEN` → 取消"。实现时发现这条会
**让双手缩放根本无法进行**：两手操作时，没在捏合的那只手**本来就是张开的**，
只要它被判定成 `OPEN`，每次都会把正在进行的拖动/缩放清掉。

改成：**只有抓着素材的那只手张开才算放手**（它的捏合随之结束 → 释放）。
"保留张开手掌作为第二种取消方式"因此仍然成立 —— 只是作用域是"这一只手"。

### 7.2 `FIST` 的作用域：从"一切"收窄到"这只手"（**真机反馈后改的**）

规格原文写的是"握拳取消一切"，实现时也照做了（全局清空）。**真机证明这个取舍错了**，
用户原话：

> "屏幕里同时有两个手时，如果一只手握拳，自动识别为无法选取，容易干扰另一个手的抓取。"

我自己在 §5 里其实预判过这个风险（"另一只手只是随意搭着、若被判成握拳"），
但当时选择"急停优先"。真机上这个代价不可接受，所以现在：

| 情况 | 行为 |
| --- | --- |
| 抓着素材的那只手握拳 | 取消**它自己**的会话（素材停在原地） |
| 什么都没抓着的手握拳 | **什么都不做**（不取消、不设重新武装、不动预览） |
| 两只手各抓一张图，其中一只握拳 | 只松开那一张 |

"每只手管自己的会话"既保住了急停，又不可能被旁观的手干扰。

### 7.3 `FIST` / `OPEN` 做成**状态**，不做成离散事件

原计划新增 `gesture-start/fist` 这类事件。实现时改成状态（`controls.fistHands`、
`pinches[].shape`），理由是：

> 取消是"此刻有没有手握拳"这件事，用**状态**表达天然幂等。
> 事件一旦被合并/丢失，急停就失效了 —— 而"合成输入被覆盖导致事件丢失"
> 这个坑在这个项目里已经踩过六次（见 `DECISIONS.md` 17.4 / 18.5）。

代价是每帧都要判一次"有没有手握拳"，收益是急停不可能被时序问题吞掉。

### 7.4 手型量取自**原始**关键点，不带快滤波

原方案（以及第 17 节的旧设计）是"给控制量单独配一条快滤波"。实现时试了，
发现它会把"张开 → 捏合"这种大跳变拖上 2 帧，**破坏"单帧就抓住"这条真机验证过的性质**。
所以手型量直接取自未平滑的关键点，抖动交给 gap 迟滞 + `FIST`/`OPEN` 的 2 帧最短保持吸收。

顺带把那条快滤波（`controlSmoother`）整个删掉了 —— 单手缩放已经移除，
它已经没有消费者，留着就是每帧白算两遍 21 个关键点。

## 8. 实现验收

### 8.1 第一轮（按规格实现）

- 单元测试：判定表每一格、**握拳的六种变体都不得被判成捏合**、
  "直捏"必须被认作捏合、优先级、gap 与 θ 两条迟滞、旋转/镜像/尺度不变性、关键点不全
- 浏览器验收：手型读数、握拳不被读成捏合、2 帧最短保持、急停取消、
  取消后不许抓回、张开手后重新抓住
- 人工过目截图 `tools/grammar-fist-stop.png`

### 8.2 第二轮：真机反馈两个问题后（本节最值得看）

真机反馈：

1. "选中后握拳，想再次选中的时候总是把我识别成握拳，但实际上我已经张开手了。"
2. "屏幕里同时有两个手时，如果一只手握拳，自动识别为无法选取，容易干扰另一个手的抓取。"

查下来是**三个独立缺陷**，全在判定与状态管理里，已全部修掉：

| # | 缺陷 | 真机表现 | 修法 |
| --- | --- | --- | --- |
| 1 | 握拳要求"四指全蜷"，而**深层捏合时无名指小指本来就会蜷进掌心** | 捏得紧就被判握拳 → 再也选不中 | 只认**食指+中指**深蜷（中指不参与捏合，是诚实信号） |
| 2 | 蜷曲阈值太松（平面 1.15），把"松开拳头但还半握着"的放松手（≈1.2）也算了进去 | 已经松开还判握拳 | 收紧到平面 `1.10` / 深度 `1.20`，并加第二把尺子（含深度的三维距离） |
| 3 | **手离开画面后槽位留着上一次的 `fist`**（非捏合手型直接 return，没清手型） | 交互层拿这份陈旧手型判断"能不能重新武装" → 门槛永远解不开 | 手型与"会话是否按住"拆成两个字段；看不到手 → `shape = other` |

第 3 条最隐蔽：它是**状态管理**问题而不是判定问题，只在"某只手曾经是握拳/捏合、
然后离开画面"时出现。合成输入脚本里两只手交替进出，把它稳定复现了
（脚本从 11.6 到 11.8 共享同一个 GestureManager，前一段留下的左手槽位把后一段锁住了）。

另外加了一道**安全阀**：重新武装最多拦 `1.5s`，到点无条件放行 ——
手型判定万一卡住，也绝不能让用户"再也抓不住任何东西"（那比多等一秒严重得多）。

回归测试（每条都对着真机现象写）：

- `handShape.test.ts`：**深层捏合不是握拳**、放松手不是握拳、
  透视缩短不改变比值（顺带纠正了我自己的一个错误假设，见 §1.1.2 的引注）
- `gestureManager.test.ts`：手离开画面后 `pinches[].shape` 必须是 `other`、
  宽限期内 `active=true` 但 `shape='other'`、一只手离开不影响另一只手
- `interactionManager.test.ts`：旁观的手握拳不影响另一只手的抓取、
  两只手各抓一张时只松开自己那张、手离开画面后重新武装立刻解除、重新武装超时放行
- 浏览器验收 **61/61**，其中新增三项：深层捏合不判握拳、放松手不判握拳、
  旁观的手握拳不干扰另一只手的抓取
- 单元测试 **275 个**全过

### 8.3 第三批（边界 + 指弹 + 录制上限）

| 项 | 覆盖 |

| `boundary.test.ts` | 五种模式的钳制、缩放/旋转/非居中锚点参与约束、素材比画幅大时居中、"任何模式都不会完全丢"的兜底 |

| `flickDelete.test.ts`（端到端） | 不透明度真的在降（是淡出不是消失）、到期真的移除、撤销后不透明度还原、弹空处无副作用、移除后不留幽灵目标 |

| `recorder.test.ts` | 时长/体积上限、`usage` 的进度与剩余秒数、停止后不再报上限、**到上限照常出片**、分片字节累计 |
| 浏览器验收 | 四角拖到画面外仍被钳回且仍可抓回、指弹装填与速度读数、淡出可撤销/到期移除、**录制到上限自动停止并保存**、**切到后台自动停录并保存**、**指弹装填门槛（半勾该装填 / 握拳不该装填，并截图调试面板）** |

**验收里踩到的两个坑（都是"脚本自己骗自己"那一类）**：

1. **把"帧数"当时间用。** 删除淡出期是 2 秒，我在脚本里喂了 90 帧就断言"到期"——
   但 rAF 一帧只有约 16ms，90 帧才 1.44 秒，根本没过期。
   `dt` 走的是真实时间，合成输入也必须按**真实时间**喂够。
2. **状态栏被覆盖。** "已到录制上限"的提示写在 `stopRecording()` **之前**，
   而它自己会写一条"录制完成"，于是提示被吃掉。验收断言"状态栏要说明原因"当场抓到，
   改成在停止完成之后写。

### 8.4 第四批（指弹装填门槛的真机标定）

真机反馈：**"食指勾住了，但指弹一直没触发"**。查下来是装填门槛定得太紧
（食指 ≤1.20 要求真拳头级别的蜷曲、gap ≥0.80 要求拇指明显离开食指），
而自然的指弹姿势两条都不满足。这一批做的就是**放宽 + 让它可诊断**：

| 项 | 覆盖 |
| --- | --- |
| `flick.test.ts` | 新增"装填门槛（真机标定）"一组 5 条：半勾能装填、拇指贴旁能装填、中指深蜷不装填、gap 0.50 不装填、与握拳阈值不重叠 |
| `gestureManager.test.ts` | 调试读数（`debug.flick`）在"正在装填的那只手"上取值，而不是永远盯着捏合中的那只手 |
| 浏览器验收 | 合成"半勾"与"握拳"两个姿势，断言前者装填、后者不装填且面板指出挡路的那一条；并输出两张调试叠层截图供人工过目 |
| 人工过目 | `tools/flick-arm-half-hook.png` / `tools/flick-arm-fist.png` 一眼能读出读数与门槛 |

**这一批又踩到两个坑（都是靠"人工过目截图"才发现的）**：

1. **面板被画布右边缘切掉。** 手机竖屏画布宽约 500px，而我把三条门槛全写进一行，
   于是**最该读的数字恰好在屏幕外**。改成"只写读数 + 只报当前挡路的那一条"，
   并让面板按可用宽度**自适应缩字号**（下限 8px），长行不再溢出。
2. **`✓` / `✗` 渲染成豆腐块。** 等宽字体栈里没有这两个字形，真机和无头浏览器都一样。
   标记改用 ASCII 的 `+` / `-`。

> ⚠️ **这一批的装填门槛已被第五批整个推翻**（截图文件也随之改名）。见 §8.5 与 §9.1。

### 8.5 第五批（指弹模型的真机重写）

真机反馈：**"弹脑瓜（拇指扣住食指尖蓄力、其余三指不动、食指弹出）试很多次都装填不上"**，
并附了调试叠层的截图。查下来不是门槛松紧的问题 —— 三条门槛描述的**是一个不存在的姿势**，
而且 `gap` 那条方向是反的（真姿势里拇指就扣在食指尖上）。详见 §9.1。这一批是**重写**：

| 项 | 覆盖 |
| --- | --- |
| `flick.ts` | 判据整条重写：装填 = `gap ≤ 0.65`（拇指扣住）+ 其余三指蜷着；弹出 = `gap` 增量 ≥0.25 + 指尖速度 ≥0.8。新增 `releasing` 阶段（真机 20fps 下常常"拇指先松一帧、食指下一帧才飞出去"） |
| `interactionManager.ts` | 去掉"正抓着东西就跳过指弹"那条，改成**删掉手里抓着的那张** —— 那条的理由正是旧的"拇指不参与"门槛，前提没了 |
| `debugOverlay.ts` | 两行改成"**扣住** / **甩开**"两段，各报读数与门槛 |
| `flick.test.ts` | 整组重写（23 条）：真机蓄力姿势能装填、**抓着图快速拖动不算**、整只手张开不算、增量不够不算、速度不够不算、甩开读数可读且保持 |
| `flickDelete.test.ts` | 新增"手里抓着的那张优先"（指尖位置故意报在别的素材上，删的仍必须是手里那张） |
| `gestureManager.test.ts` | 合成手姿势换成真机读数；挡路的那条从"中指深蜷"改成"其余三指张开" |
| 浏览器验收 | 姿势换成 `hook` / `open-fingers`；"指弹被识别"那条改为直接跟 `minTipSpeed` 比较（不再硬编码 `1.5`） |
| 人工过目 | `tools/flick-arm-hook.png` / `tools/flick-arm-open-fingers.png` |

**这一批的核心教训**：前两批都在"调门槛的数字"，但真正错的是**门槛描述的那个动作**。
真机读数（食 1.52 / gap 0.45 / 中 0.91）三条**全不达标**，正是"模型错了"而不是"数字偏了"的信号 ——
**当一条门槛要求的方向和用户的自然动作相反时，再放宽也没用。**
